== Additional Extensions

Since 3D Tiles 2.0 tilesets are valid glTF 2.1 files, any extension compatible with glTF 2.1 can be used. Many core content features of 3D Tiles 2.0 are actually powered entirely by glTF extensions. Supporting certain types of content means supporting these glTF extensions.

=== Architectural, Engineering, and Construction Rendering

// TODO: FIX THE SHALLs. Make supports.

3D Tiles 2.0 shall support edge rendering for AEC workflows through the glTF extensions `KHR_mesh_primitive_restart` and `EXT_mesh_primitive_edge_visibility`. Conforming implementations shall recognize both extensions in tile content and shall either render the content according to the extension definitions or report the extension as unsupported in accordance with glTF 2.1. 

For the styling of points and lines in CAD content, 3D Tiles 2.0 shall support the `BENTLEY_materials_line_style` and `BENTLEY_materials_point_style` glTF extensions. These extensions define the properties used to represent hidden and conceptual elements common in civil and engineering rendering workflows. 

Implementations shall support `EXT_textureInfo_constant_lod` to maintain consistent texture pattern scale across zoom levels. Implementations should support `BENTLEY_materials_planar_fill` to mitigate z-fighting between co-located surfaces such as labels, roads, and overlapping infrastructure. 

=== Time-dynamic Content 

// TODO: Verify what we should call this.

Using the `3DTILES_conditional_content` extension, implementations may support time-dynamic 3D tiles, enabling multiple representations of the same spatial region within a single tileset (for example, temporal states of terrain, design-model revisions, or alternative geometries such as point clouds and meshes). 

Any tile may be tagged with one or more attribute key/value pairs. A tileset shall not require every tile to be tagged; untagged tiles shall be treated as unconditional. Clients shall select tile content by evaluating these tags against a selection expression supplied at runtime. Where no selection expression is supplied, clients shall render the default content declared by the tileset author. 

Authoring tools may use time-dynamic 3D tiles to publish incremental updates without rewriting an entire tileset. 

=== Voxels

3D Tiles 2.0 supports voxel volumetric datasets. Conforming voxel tilesets shall use the `EXT_primitive_voxels`, the `3DTILES_shape_ellipsoid_region`, and the `3DTILES_shape_cylinder_region` glTF 2.1 extensions in combination with the implicit tiling mechanism defined in 3D Tiles 2.0. 

Both dense and sparse voxel volumes shall be supported. Voxel payloads may be uncompressed, or may be compressed using gzip, the glTF `EXT_meshopt_compression` extension, the glTF `KHR_meshopt_compression` extension, or a combination of the available methods.

=== 3D Gaussian Splatting

3D Tiles 2.0 shall support 3D Gaussian Splatting content via the `KHR_gaussian_splatting` glTF extension. Conforming implementations claiming the Gaussian Splatting conformance class shall recognize this extension. 

Implementations shall support `KHR_gaussian_splatting_compression_spz_2`, which defines compression of splat data using the SPZ format. Uncompressed splat content may be used where compression is not required. Splat tilesets shall be compatible with the hierarchical level-of-detail mechanism of 3D Tiles, such that clients may stream and cull splat content using the same traversal rules as other tile content types.
